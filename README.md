# smart-noryangjin

노량진 수산시장 경매 시세를 매일 수집해 최근 30일 등락 추이와 **가성비 매수 구간**을 Plotly 대화형 차트로 보여주는 개인 대시보드입니다. 차트에 마우스를 올리면 일자별 고가(산지·규격 포함), 구간 상한·하한, 평균가, 저가가 한 번에 표시됩니다.

노량진수산물도매시장에서 거래되는 **모든 어종**을 매일 수집합니다(2026년 9월 기준 30일 동안 151종). 페이지는 두 개의 탭으로 되어 있습니다.

- **주간 경락량:** 최근 5영업일 경락량(kg), 합계, 바로 앞 5영업일 대비 증감을 표로 보여 줍니다. 기본 표에서는 넙치·농어·참돔을 자연산·양식, 감성돔·돌돔을 국산·수입으로 나눕니다. ‹ › 버튼으로 이전 주를 볼 수 있고, 행을 누르면 그 어종의 시세 차트로 이동합니다.
  - **상태:** 활어, 선어, 전체 중에서 고릅니다.
  - **표시 어종:** 기본 표, 경락량 상위 30종, 상위 50종, 전체 어종 중에서 고릅니다. 상위 모드는 그 주의 경락량 순서로 순위를 붙입니다.
  - **어종 추가:** 검색창에 어종명(흔히 쓰는 이름도 가능, 예: 킹크랩)을 넣고 추가하면 행이 붙고, ×로 뺄 수 있습니다. 보는 사람의 브라우저에 저장됩니다.
- **어종별 시세:** 날짜별 낙찰 고가·평균가(수량 가중)·저가를 선으로, 경락량을 막대로 그리고, 평균가와 고가 사이의 가성비 구간을 음영으로 표시합니다(아래 '가성비 구간 계산'). 가격선 색은 주식 차트 관례(고가 빨강, 저가 파랑, 평균가 주황, 밴드 보라)를 따릅니다.
  - **어종 검색:** 검색창에 이름을 입력하면 어종 칩이 걸러지고, Enter로 첫 결과를 고릅니다. '킹크랩'처럼 흔히 쓰는 이름으로도 찾을 수 있습니다. 검색하지 않을 때는 주요 어종과 거래량 상위 어종만 보이고 '더 보기'로 전체를 펼칩니다.
  - **즐겨찾기(★):** 누른 어종이 맨 앞에 오고 다음 방문 때 먼저 선택됩니다(보는 사람의 브라우저에만 저장).
  - **상태·산지·규격:** 산지와 규격 칩은 한 번 누르면 포함, 한 번 더 누르면 제외(취소선), 세 번째에 해제됩니다.
  - **표시 선택박스:** 고가, 평균가, 저가, 가성비 구간, 작년 같은 시기, 직전 3개월 평균, 경락량을 각각 켜고 끌 수 있습니다.
  - **작년·직전 3개월 비교:** '작년 같은 시기' 점선은 1년 전 같은 날짜의 평균가, '직전 3개월 평균' 선은 최근 거래일 앞 3개월의 평균가입니다. '가격 수준' 카드는 최근 평균가가 작년 같은 달과 직전 3개월보다 몇 % 높거나 낮은지, 작년 같은 달 일별 평균가 가운데 어디쯤인지 게이지로 보여 줍니다(아래 '가격 비교 기준').
  - **확대:** 차트 위 ＋ 확대, － 축소, ◀ ▶ 이동, 전체 보기 버튼을 씁니다. PC에서는 가로로 드래그해 확대하고 더블클릭으로 되돌립니다. 확대하면 세로축이 보이는 구간에 맞춰지고, 16일 이하가 보이면 값 라벨이 나타납니다. 휴대폰에서는 드래그 확대를 꺼서 페이지 스크롤과 겹치지 않습니다.
  - **마우스 호버:** 날짜별 정보가 고가, 구간 상한, 구간 하한, 평균가, 저가, 작년 같은 시기, 직전 3개월 평균, 경락량 순서로 나옵니다.

바탕 색상은 #3368A0, #66A3BF, #C8DFDB, #F2EFE7을 씁니다.

## 로컬 실행

```bash
pip install -r requirements.txt
python pipeline.py                     # 공식 홈페이지에서 오늘·어제 전체 어종 시세 수집
BACKFILL_DAYS=30 python pipeline.py    # 원본이 없는 지난 30일도 채움
DATA_SOURCE=sample python pipeline.py  # 사이트 접속 없이 샘플 데이터로 화면만 확인
```

## 배포 (GitHub Pages)

1. 저장소 **Settings → Pages → Build and deployment**에서 Source를 `Deploy from a branch`, Branch를 `main` / `(root)`로 저장합니다.
2. **Actions → Update market dashboard → Run workflow**를 한 번 수동 실행하면 이후 매일 06:45 KST에 갱신됩니다. GitHub 예약 실행은 붐비는 시간에 늦어질 수 있어, 정각을 피해 45분으로 두었습니다. 기록을 새로 채울 때는 `backfill_days`에 30을 넣습니다.

   공식 홈페이지는 특정 IP의 연결을 막는 일이 있습니다(2026-10-21). 그래서 수집은 실패하면 새 실행기에서 두 번 더 시도하고, 원본이 없는 날짜는 7일 전까지 다음 실행이 채웁니다. 해외 IP가 계속 막히면 국내 PC를 self-hosted runner로 등록하고 저장소 변수 `UPDATE_RUNNER`에 그 라벨(예: `self-hosted`)을 넣으면 수집이 그 PC에서 돕니다.

## 수집 방식 (노량진수산물도매시장 공식 홈페이지)

`noryangjin.py`는 공식 홈페이지 **수산물가격정보 → 어종별경락시세**(`/nsis/miw/ko/info/miw3130`) 화면의 엑셀 다운로드 요청을 그대로 재현합니다.

1. 화면(`miw3130`)을 GET 해서 세션 쿠키를 받습니다. 사이트가 잠시 응답하지 않을 때를 대비해 10초, 20초 간격으로 최대 3번 시도합니다.
2. `excel/miw3130`에 조회일(`searchStartDe`, `searchEndDe`, `YYYY.MM.DD`)을 POST 합니다. 어종명(`kdfshNm`)을 비워 보내면 그날 거래된 모든 어종이 한 번에 옵니다. 매일 자동 실행은 오늘·어제 두 번만 요청합니다.
3. 응답 표(어종, 산지, 규격, 포장, 수량, 중량, 낙찰고가, 낙찰저가, 평균가)를 `data/daily/YYYY-MM-DD.csv`로 저장합니다. 휴장일은 행이 없어 건너뜁니다. 응답이 요청 한도(10,000행)에 닿으면 잘렸을 수 있어 실패로 처리합니다.
4. 최근 30일 원본 행을 페이지에 넣습니다. 어종 이름은 `(활)`·`(선)` 표기를 뗀 공식 표기로 나누므로 `방어`와 `잿방어`, `우럭`과 `우럭조개`가 섞이지 않습니다. 가격은 kg 단위 거래만 쓰고, 경락량은 상자 단위를 `수량 × 중량`으로 환산합니다.
5. 해석에 실패한 응답은 워크플로 아티팩트 `debug-response`로 올리고 작업을 실패 처리합니다.

### 어종 이름과 구분

- 공식 표기와 흔히 쓰는 이름이 다른 어종은 `LABELS`로 함께 보입니다. 감숭어(숭어), 줄돔(돌돔), 전어(황전어), 왕게(킹크랩)입니다.
- 자연산·양식, 국산·수입은 원본에 구분이 없어 산지로 나눕니다(`KIND_RULES`). 공개 입하 통계와 산지별 경락 수량을 대조해 넙치 제주도, 참돔 일본·통영, 농어 중국을 양식으로 봅니다.
- 주간 표의 행은 `TABLE_ROWS`에서 바꿉니다. 새 어종은 설정 없이 자동으로 수집됩니다.

기간·비율은 `pipeline.py` 상단의 `WINDOW_DAYS`, `LOWER_RATIO`, `UPPER_RATIO`로 조정합니다.

## 가성비 구간 계산

가성비 구간은 **평균가 + (고가 − 평균가) × 60~80%**입니다. 평균가는 그날 kg 거래의 평균가를 거래 수량으로 가중한 값입니다.

- 수산물은 너무 싼 물건은 원물 상태가 나쁘므로, 구간을 평균가보다 위, 고가 가까이에 둡니다.
- 평균가는 그날 저가보다 낮을 수 없으므로 구간이 저가선 아래로 내려가지 않습니다. 처음 쓰던 '고가 × 70~80%'는 흰다리새우처럼 한두 가격으로만 거래되는 날 저가 아래로 내려갔습니다(2026년 9~10월 활어 어종·날짜의 19%).
- 고가와 평균가가 같은 날(한 가격 거래)은 구간이 그 가격 한 점이 됩니다.

| 예 (2026-10-20) | 고가 | 평균가 | 고가 × 70~80% (처음 방식) | 평균가~고가 60~80% (지금) |
|---|---|---|---|---|
| 넙치 | 37,000 | 27,768 | 25,900~29,600 | 33,307~35,154 |
| 방어 | 26,000 | 12,708 | 18,200~20,800 | 20,683~23,342 |
| 흰다리새우 | 18,000 | 17,300 | 12,600~14,400 (저가 아래) | 17,720~17,860 |

비율은 `pipeline.py`의 `LOWER_RATIO`, `UPPER_RATIO`로 바꿀 수 있습니다.

## 알림 (ntfy)

매일 수집이 끝나면 `alerts.py`가 최근 거래일을 판정해 새 알림을 [ntfy](https://ntfy.sh) 주제로 보냅니다. 같은 날 같은 알림은 `data/alerts_sent.json`에 기록해 한 번만 보냅니다. 지난 날짜를 채우는 기간 백필에서는 보내지 않습니다.

1. 휴대폰에 ntfy 앱을 설치하고, 남이 짐작하기 어려운 주제 이름(예: `noryangjin-7f3k9q2m`)을 정해 구독합니다.
2. 저장소 **Settings → Secrets and variables → Actions → Secrets**에 `NTFY_TOPIC`으로 그 주제 이름을 넣습니다. 이 값이 없으면 알림을 판정만 하고 보내지 않습니다.
3. 대시보드 **알림 설정** 탭에서 규칙을 편집하고 저장합니다. 규칙은 저장소의 `alerts.json`에 들어갑니다.

규칙 종류는 다음과 같습니다.

- **자동 감시:** 직전 10거래일 하루 거래 건수가 5건 이상인 어종·상태에서, 평균가나 입하량이 평소 움직임보다 크게 벗어나면 알립니다. 민감도는 낮음·보통·높음 중에서 고르며, 보통이면 하루 1~2건 정도입니다(2026-09~11 원본 기준).
- **내 규칙:** 어종(`*`는 표본이 많은 어종 전체)과 상태를 정하고 조건을 5개까지 둡니다. 조건은 '모두 만족(AND)' 또는 '하나라도 만족(OR)'으로 묶습니다.
  - **변화 조건:** 항목(평균가·고가·저가·입하량), 기준(직전 거래일 또는 직전 5·10·20거래일 평균), 방향(상승·하락·상승·하락), 값과 단위(%, 원·kg, 배)를 정합니다. 배수로 하락을 고르면 기준의 그 분의 1 이하를 뜻합니다(2배 하락 = 절반 이하).
  - **수준 조건:** 항목이 지정한 원·kg 이상이거나 이하이면 걸립니다.
  - 예: '활 방어: 입하량이 직전 5거래일 평균의 2배 이상 **그리고** 평균가가 직전 거래일보다 10% 이상 내림'. 평소 500kg 들어오던 방어가 1,000kg 들어오면서 값이 빠진 날을 잡습니다.

입하량은 그날 낙찰된 수량 × 중량의 합(kg)이라 시장이 발표하는 입하량과 조금 다를 수 있습니다. 예전 형식(조건 필드가 규칙에 바로 있는 규칙)도 조건 하나짜리 규칙으로 읽습니다.

'GitHub에 저장'에는 이 저장소의 Contents 읽기·쓰기 권한만 준 fine-grained 토큰을 씁니다. 토큰은 그 브라우저에만 저장됩니다. 토큰 없이 쓰려면 '설정 복사' 후 'GitHub에서 직접 편집'에 붙여 넣습니다.

## 가격 비교 기준

모든 비교는 평균가(kg 거래, 수량 가중)로 하고, 어종과 상태(활어·선어)만 맞춥니다. 산지·규격 필터는 비교에 적용하지 않습니다.

- **작년 같은 달:** 최근 거래일이 2026년 11월이면 2025년 11월 전체 거래의 평균가입니다. 카드에는 그 달 일별 평균가 가운데 지금 값보다 낮은 날의 비율도 나옵니다.
- **작년 같은 시기(차트):** 차트의 날짜마다 1년 전 같은 날짜의 평균가입니다. 그날 거래가 없으면 앞뒤 3일 안의 가장 가까운 거래일 값을 씁니다.
- **직전 3개월 평균:** 최근 거래일 앞 3개월(예: 11/4 기준 8/4~11/3)의 평균가입니다.

페이지에는 이 계산에 필요한 기간만 '어종|상태'별 일별 요약(평균가·고가·저가·수량·경락량)으로 넣어 크기를 줄입니다. 과거 원본은 **Actions → Update market dashboard → Run workflow**에서 `backfill_from`·`backfill_to`를 지정해 채웁니다. 요청이 몰리지 않도록 한 번에 `backfill_limit`일(기본 60일)까지, 3초 간격으로 받고, 거래가 없던 날은 `data/no_trade.txt`에 적어 다시 요청하지 않습니다.
